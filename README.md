# 自主进化 · AutoEvolve

> 大多数 AI 插件在「用」你的提示词。这一个会「改」你的提示词 —— 而且改完自己验收。

`astrbot_plugin_auto_evolve` 是一套提示词自我进化引擎。它不陪你聊天，也不替你想台词。
它只做一件事：**在你已经写好的人格文本上做外科手术**，然后把刀口、理由、验证结果一起摊给你看。

到点把这几天你和 Bot 的对话重读一遍，找出三类问题 —— 反复出现的模板句、写了却没生效的规矩、
和真实对话脱节的表述。每条都写成「改哪一句 / 改成什么 / 为什么改」，先自证再动手，
你点头才落库；落库前有四道关，落库后有抽样复验，改坏了 `/撤` 回滚。

一句话：**先自证，再动手；动手留底，动完复验。**

---

## 它凭什么敢改自己的提示词

市面上「AI 自省」类插件大多止步于「生成一段反思」。问题在于：一段反思无法验证，
落到提示词里就是一次不可回滚的赌博。AutoEvolve 把这件事拆成了一条可审计的链路：

| 环节 | 别的做法 | 这里的做法 |
|---|---|---|
| 该不该动 | 到点就动 | 三层门槛：轮数、信息量、置信度 |
| 改什么 | 生成一段新提示词 | 生成**逐字定位**的补丁：old 必须在原文里唯一命中 |
| 会不会改坏 | 靠模型自觉 | 四道关：体检 / 字数上限 / 累计漂移 / 抽样复验 |
| 改完看不出来 | 只报「已更新」 | 每条补丁带 `layer`、`why`、`confidence`，回执逐条列 |
| 改错了 | 手动翻备份 | `/撤` 一条命令回滚，备份按天保留 |

**闭环**：复盘 → 定位 → 自证 → 审批 → 落库 → 复验 → 观察归档 → 下一轮更准。
每一轮跑完，`obs_log` 会记下这一轮被反复指出的问题；下一轮把它们带进提示词 ——
所以它不是「每次都从零开始反思」，而是**带着上一轮的账本继续**。

---

## 核心设计：四个「不」

1. **不整份覆盖**。补丁按 old→new 逐条打，库里文本变了就整批拒收，绝不拿一份旧快照盖掉你后来的修改。
2. **不重复造句子**。新句子和人格里已有的某行说的是同一件事就拦（整行相似度 / 含糊词重合 / 字符 bigram 三路信号）。
3. **不越层**。人格管「对用户说什么、怎么说」，工具怎么调写 description，出站怎么削写补丁 —— 一条补丁只能落一层，两处都写后面那条一定赢。
4. **不删锚点**。你自己在 `anchors.json` 里钉死的句子，补丁删了就不落库。

## 功能

### 1. 定时复盘

按 `schedule_times`（默认 `01:16`、`13:20`）自己醒，读 `lookback_turns` 条对话。
想立刻跑一次：`/反思`。手动触发会跳过前三层门槛 —— 你亲口要的，它不跟你讲条件。

### 2. 三层门槛（该不该动）

| 门槛 | 默认值 | 不到怎么办 |
|---|---|---|
| 新轮数下限 `tier1_turns` | 8 | 直接拒：「这段时间新对话太少，不值得动人格」 |
| 记账线 `tier2_turns` | 20 | 只记一笔进 `tier1_log`，不动人格 |
| 信息量 `gate_threshold` | 0.35 | 记 `last_gate`，回「这几天聊得太薄（信息量 0.23 < 0.35）」 |

信息量不是字数，是四项加权：对话深度 0.45、体量 0.25、双方占比 0.15、问句比例 0.15。
一堆「在吗」「嗯」凑不出信息量，这正是它要拦的东西。

### 3. 补丁长什么样

```json
{
  "persona_patches": [
    {
      "section": "【日常】",
      "old": "逐字原文，连标点一起抄",
      "new": "替换后的文字",
      "reason": "为什么改，能减几个字",
      "layer": "persona",
      "why": "为什么不能放到别的层",
      "confidence": 0.82
    }
  ]
}
```

- `layer` 五选一：`persona`（人格文本）/ `rules`（硬规则）/ `description`（工具描述）/ `outbound`（出站清洗）/ `lexicon`（词表数据）。
- `confidence < min_confidence`（默认 0.7）的补丁只报不落。
- 一轮里 `persona` 层最多落 `persona_per_round` 条（默认 2），多出来的进 `deferred_patches`，下一轮接着提。

### 4. 四道关（落地前）

| 关 | 拦什么 | 开关 |
|---|---|---|
| 人格体检 | 口头禅被削、主动词被删、加了压制/请示类说法、加总结套话 | 常开 |
| 字数上限 | 单次改动超过 `delta_percent`（默认 10%） | `enforce_delta` |
| 累计漂移 | 相对基线累计超过 `max_total_drift_percent`（默认 15%） | 常开 |
| 采样复验 | 改后抽样重跑，口语词/书面词/主动性/递话任一项明显退化 | `验证.enabled` |

采样只做参考、不做拦截依据：同一条提示词跑两遍，指标本来就会抖。真正拦人的是前面三关 —— 它们是文本操作，零假阳性。

### 5. 审批与回滚

补丁默认进队列等你点头：

```
/补丁          看队列
/批 3          落第 3 号
/批 3 1,3      只落这几条
/批 3 go       落整包
/撤 3          回滚第 3 号
```

### 6. 观察画像与提示词演化

每轮结论按类别归档进 `obs_log`（模板句 / 含糊 / 表达密度 / 话太满 / 露怯 / 主动性 / 称呼 / 口语）。
下一轮把「最近反复被指出的」（出现 ≥2 轮）带进提示词 —— 让反思越来越知道该盯哪儿。

提示词本身也在演化：同一条侧重撞上 `min_hits` 次才写进侧重段，`decay_days` 天过期，
`match_ratio` 判两条是不是同一条。这一层默认只观察、不改写你的提示词。

### 7. 词表补丁

`layer=lexicon` 的补丁不进人格，落到 `lexicon.json`：只增不删，类别对不上就拒。
用词偏好是数据，不该混在提示词里，也不该去改别的插件。

### 8. 代码补丁

只报明确的 bug（缩进错、变量名错、逻辑漏洞），风格问题不提。
路径分三色：`data/plugins/` 绿区直接改；`backend/app/astrbot/core/` 黄区要你批；其余红区只报不动。
改前存 `.bak`，改后 `py_compile` 校验，失败自己滚回去；插件路径额外查一次有没有 `Star` 子类（装了不生效等于没改）。

## 一次复盘走完是这样

```
① 到点 / /反思
        ↓
② 拉对话（记忆库优先，读不到退回框架上下文）
        ↓  上次 msg_id 之后的新消息
③ 三层门槛（tier1 / tier2 / 信息量）
        ↓  不够就只记一笔，到此为止
④ 喂给模型：人格全文 + 对话 + 反复被指出的 + 上轮没落地的
        ↓
⑤ 解析补丁 → 置信度分流（<0.7 只报不落）→ 按 layer 分桶
        ↓
⑥ 四道关（唯一 / 查重 / 体检 / 锚点）+ 分桶限额
        ↓
⑦ 排队等批，或按配置直接落库（先备份）
        ↓
⑧ 落库后抽样复验（分组指标 + 结构指标）
        ↓
⑨ 回执：改了几处、哪个文件、验证过没过、备份在哪
```

## 快速开始

1. 把整个目录放进 `AstrBot/data/plugins/`，重启（或在 WebUI 插件页重载）。
2. 零外部依赖：只用 AstrBot 自带 API 和标准库。
3. 打开配置，至少填两项：`基本设置.target_umo`（复盘哪个会话）、`提示词.provider_id`（用哪个模型复盘）。
4. 想先看效果不落库：`人格改法.dry_run = true`，跑一轮看回执。
5. 觉得靠谱了再关掉 `dry_run`，补丁就会进队列等你 `/批`。

### 命令

| 命令 | 作用 |
|---|---|
| `/反思` | 立刻跑一轮（跳过前三层门槛） |
| `/反思状态` | 上次跑到哪、下次几点、几个补丁等着批 |
| `/补丁` | 列出等着的补丁：改哪段、改成什么、为什么改 |
| `/看 3` | 同 `/补丁`，看单条详情 |
| `/批 3 [go\|1,3]` | 批第 3 号（整包或指定几条） |
| `/撤 3` | 撤第 3 号 |

### 配置分组

| 组 | 关键项 |
|---|---|
| 基本设置 | `enabled`、`schedule_times`、`target_umo`、`lookback_turns`、`min_new_turns`、`tier1_turns`、`tier2_turns` |
| 人格改法 | `persona_id`、`delta_percent`、`enforce_delta`、`auto_apply_persona`、`max_total_drift_percent`、`persona_per_round`、`gate_enabled`、`gate_threshold`、`min_confidence`、`dry_run` |
| 代码补丁 | `code_patch_enabled`、`allowed_dirs`、`auto_apply_code`、`import_check` |
| 提示词 | `reflection_prompt`、`provider_id`、`obs_window` |
| 验证 | `enabled`、`prompt_ids`、`repeat`、`struct_check` |
| 提示词演化 | `enabled`、`min_hits`、`max_focus`、`decay_days`、`match_ratio` |
| 备份 | `keep_days` |
| 词表 | `lexicon_path` |

> 能被主人「选一选、填一填」的，一律做成配置字段；技术约束（比如「old 必须唯一」）不进配置。

## 数据与文件

| 路径 | 内容 |
|---|---|
| `plugin_data/astrbot_plugin_auto_evolve/state.json` | 基线、历史、队列、观察日志 |
| `plugin_data/astrbot_plugin_auto_evolve/backups/` | 每次落库前的快照（按 `keep_days` 清理） |
| `plugin_data/astrbot_plugin_auto_evolve/anchors.json` | 你自己钉的「不许删」句子，可选 |
| `plugin_data/astrbot_plugin_auto_evolve/lexicon.json` | 用词偏好表 |

`anchors.json` 例子：

```json
{
  "称呼不许丢": "叫用户的名字",
  "不报过程": "改了几处都不说"
}
```

## 常见排查

| 现象 | 先看 |
|---|---|
| 到点没跑 | `enabled` 开了没、`schedule_times` 格式是不是 `HH:MM` |
| 一直说「新对话太少」 | `tier1_turns` / `min_new_turns` 调小，或手动 `/反思` |
| 一直说「聊得太薄」 | `gate_threshold` 调低，或关 `gate_enabled` |
| 补丁全被拒 | 多半是 `old` 没逐字对上：连标点一起抄，别用省略号 |
| 补丁不落地 | `dry_run` 还开着，或 `auto_apply_persona` 关着 |
| 命令没反应 | 先确认发命令的是管理员；再确认 `/` 前缀没被改 |
